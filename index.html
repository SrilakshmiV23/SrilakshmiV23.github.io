Individual project, Spring 2026

ForensicsDetective: PDF Provenance Detector

A cybersecurity forensics tool that tells whether a PDF was created in Microsoft Word, Google Docs or Python/ReportLab. It supports document authentication and spotting insider threats, such as company files exported from unapproved tools.

Each PDF's raw bytes become a grayscale image, and SVM and SGD classifiers learn the fingerprint each tool leaves behind.

  • Python
  • scikit-learn
  • SVM
  • SGD
  • ReportLab
Full case study
Problem
Knowing which tool produced a document helps with attribution, authenticity checks and insider-threat investigations, for example spotting company files exported from an unapproved platform.
Data
  • About 398 PDFs exported from Microsoft Word, built from Wikipedia articles.
  • Google Docs PDFs with the same content, generated through the Google Drive API.
  • PDFs generated in Python with ReportLab.
  • A convert.py script batch-converts the documents.
Approach
Read each PDF's raw bytes and map every byte value (0 to 255) to a pixel, turning the file into a grayscale image. Train SVM and SGD classifiers on those images.
Results
  • Word vs. Google Docs: 97.5% accuracy for both SVM and SGD, with 1 error in 40 test samples and 100% precision on Google Docs.
  • Word vs. Google Docs vs. Python: 98.3% (SVM) and 100% (SGD), with training under one second.
  • Python-generated PDFs are visibly darker: mean pixel intensity of 73.17, against about 121 for Word and Google Docs.
Next
Validate at full scale and on real forensic samples, add LibreOffice PDFs and stripped metadata, and try CNN models.

Smart-Home Battery Energy Management with Reinforcement Learning

An individual applied-RL project: agents decide each hour whether a home battery should charge, discharge or wait, to cut the household's electricity bill.

  • Real data: NYISO Zone A (Western New York) electricity prices with NREL household demand and solar generation.
  • Compared a price-threshold baseline, tabular RL and a Deep Q-Network (DQN).
  • Measured every method against a perfect-information benchmark of the best possible daily cost.
  • Studied how a peak-usage penalty changes the learned charging policy and the daily cost.
Full case study
Problem
Electricity prices change every hour. A home battery saves money only if it charges when power is cheap and discharges when it is expensive, while still covering the home's demand.
Data
Real NYISO Zone A (Western New York) electricity prices, combined with NREL household demand and solar generation profiles.
Methods
  • A price-threshold baseline rule, the strategy in the demo.
  • Tabular reinforcement learning.
  • A Deep Q-Network (DQN) agent.
  • A perfect-information benchmark that knows the whole day in advance and gives the best possible daily cost.
Study
Added a peak-usage penalty to see how it changes the learned charging policy and the daily cost.
Role
Individual project: I designed the environment, built every method and ran the comparisons.
